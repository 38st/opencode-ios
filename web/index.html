Pair your phone

Connect Opencode on your iPhone or iPad to the opencode server on your computer, then turn on notifications so a session can reach you when it needs an answer.

1. Pair your phone

The app talks directly to your own opencode server. Nothing passes through a cloud service.

  1. Use opencode 2.0.25 or later on your computer, and start it as you usually do.
  2. Create a pairing code. On the same computer, run:
    opencode pair

    It prints a pairing link and a QR code. A code works once and expires after five minutes; run the command again for a new one.

  3. Add the server in the app. Open Opencode, tap Add server, then Scan QR code, or paste the pairing link.
  4. Allow local network access when iOS asks, so the app can reach your computer on your Wi-Fi.

Away from home, the app needs an HTTPS address for your server, such as an opencode tunnel, tailscale serve or your own reverse proxy. On your home network it can use plain HTTP, and marks those addresses as unencrypted.

2. Enable notifications

Notifications need a small plugin in your opencode server. The app works without it; you just won't hear from it while it's closed.

  1. Install the plugin on your computer:
    opencode plugin add @opencode-ios/opencode-mobile-push

    Then restart opencode so it loads the plugin.

  2. Turn notifications on in the app. Open the server's settings, choose Notifications, tap Enable notifications, and allow them when iOS asks.
  3. Check it works. Under the server's name, the plugin shows as installed. Tap Send test push.

Or send directly to Apple. If you build the app yourself with your own bundle ID, the plugin can skip the relay and send to Apple with your own APNs key (a .p8 file from the Apple Developer Program, kept with chmod 600). Add an apns option to the plugin in your opencode configuration; the plugin's README shows how.

Each notification is encrypted on your computer for your phone. The relay that hands it to Apple only sees a generic alert, and cannot read or answer it. When you approve from a notification, your phone first checks the request with your server again, directly. Requests marked high-risk can only be approved in the app, and "always allow" exists only in the app.

No server yet?

Tap Try a demo on the app's first screen. The demo plays a recorded session with sample data, needs no server and sends nothing over the network.

Opencode is an independent open-source client for opencode servers.
