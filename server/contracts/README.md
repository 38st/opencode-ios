# Push contracts

The single source of truth for what the opencode-ios app, the push plugin and the relay exchange. The TypeScript code in `src/` is used by the plugin (a vendored copy) and the relay; the Swift package `OCPushCore` reads byte-identical copies of the JSON files and runs every vector in `vectors/`.

| File | What it defines |
| --- | --- |
| `constants.json` | Names, the relay's default URL, the HPKE suite and `info`, padding buckets, payload limits, the per-kind alert text, category, interruption level, priority and lifetime, rate limits, presence, Live Activity timing and APNs limits |
| `risk-rules.json` | Risk tiers for permission requests |
| `schema/envelope.schema.json` | The `oc` object in the APNs payload |
| `schema/payload.schema.json` | The sealed plaintext |
| `schema/activity-state.schema.json` | The Live Activity content state, which travels in plaintext |
| `src/apns.ts` | The APNs requests (alert and Live Activity), provider-token signing and caching, and response mapping, shared by the relay and the plugin's direct mode |
| `vectors/*.json` | Test vectors, generated by `scripts/generate-vectors.ts` except `rfc9180-a23.json` |

Commands: `npm ci`, then `npm test` (type check, then Vitest), `npm run generate` to rewrite the vectors and `node scripts/generate-vectors.ts --check` to confirm they are current. Changing a contract means changing the JSON or `src/`, regenerating the vectors, and running `node Tools/sync-push-contracts.mjs` and `server/plugin`'s `npm run sync-contracts` so the Swift and plugin copies match.

The payload, digest, padding and envelope rules below are normative. Where the text and the code disagree, the vectors decide.

## Kinds

| Kind | Sent when | Category the extension sets | Interruption level | APNs priority | Lifetime |
| --- | --- | --- | --- | --- | --- |
| `permission` | A permission request is still pending after the grace period | `PERMISSION`, or `PERMISSION_HIGH_RISK` | `time-sensitive` | 10 | 600 s |
| `question` | A form is still pending after the grace period | `QUESTION` | `time-sensitive` | 10 | 600 s |
| `finished` | A root session's execution succeeded | `FINISHED` | `active` | 10 | 3,600 s |
| `failed` | A session's execution failed | `FAILED` | `active` | 10 | 3,600 s |
| `resolved` | A request that was pushed has been answered, or ended without an answer | `OPEN_ONLY` | `passive` | 5 | 600 s |
| `test` | The app asked for a test push | `OPEN_ONLY` | `active` | 10 | 300 s |

### Categories and actions fail closed

These rules keep a notification from approving anything that nobody checked:

1. The APNs payload's category is always `OPEN_ONLY` (`apns.category`), whatever the kind. Only the Notification Service Extension, after it has opened the envelope and classified the payload, sets the kind's category from the table above. If the extension fails, crashes, is killed or runs out of time, the alert keeps `OPEN_ONLY` and offers no action.
2. The app's notification action handler refuses every action except Open unless it finds the extension's matching `shown/<requestID>.json`, which records the digest and summary the user saw.
3. Before acting, the handler fetches the request again, recomputes its digest, and classifies it with its own copy of `risk-rules.json`. It never trusts the payload's `risk`: a high-risk request is never approved from a notification, whatever the payload says.

## Envelope

```json
"oc": { "v": 1, "kid": "…", "kind": "permission", "exp": 1800000600, "enc": "…", "ct": "…" }
```

- `v`: 1.
- `kid`: the device's key ID for one paired server, chosen by the app: 16 to 64 characters of `[A-Za-z0-9_-]`.
- `kind`: one of the kinds above.
- `exp`: Unix seconds, an integer from 0 to 4,102,444,800. The envelope is expired once `now >= exp`.
- `enc`: the 32-byte X25519 encapsulated key.
- `ct`: the ciphertext and 16-byte tag of the padded plaintext: 528, 1,040 or 2,064 bytes, so at most 2,752 characters once encoded, under the 3,072-character limit.

Binary fields are base64url without padding (RFC 4648 §5). Decoders reject any other character, `=` padding, a length of 1 mod 4, and non-zero unused trailing bits.

### Encryption

HPKE (RFC 9180) in auth mode, which proves to the device that the plugin sealed the payload:

- KEM `DHKEM(X25519, HKDF-SHA256)` (0x0020), KDF `HKDF-SHA256` (0x0001), AEAD `ChaCha20-Poly1305` (0x0003);
- recipient: the device's X25519 public key for this server; sender: the plugin's static X25519 key pair, whose public key the device pinned at registration;
- `info` = the UTF-8 bytes of `opencode-ios push v1`;
- `aad` = the UTF-8 bytes of `oc1|<kind>|<exp>|<kid>`, with `exp` in decimal without leading zeros. This binds every field the relay can read to the ciphertext;
- one message per HPKE context (sequence number 0).

Keys are raw 32-byte X25519 keys (RFC 7748), which is CryptoKit's `rawRepresentation`, encoded as base64url wherever they travel as text.

### Opening

Implementations check in this order and report the first failure with these codes:

1. `malformed`: not an object, or a field is missing or invalid as described above. A `v` that is an integer other than 1 is `unsupportedVersion` instead, whatever the other fields look like.
2. `expired`: `now >= exp`.
3. `unknownKey`: no key for `kid`.
4. `authentication`: HPKE setup or AEAD decryption failed. A changed `kind`, `exp` or `kid`, a different sender, or a changed `enc` or ciphertext all land here.
5. `padding`: the decrypted bytes are not validly padded.
6. `payload`: the plaintext is not UTF-8 JSON, is not an object, or breaks the payload rules below.
7. `mismatch`: the payload's `kind` or `exp` differs from the envelope's.

## Payload

The plaintext is an RFC 8785 serialization of an object with these members. `v`, `kind`, `server`, `exp` and `pending` are always present. Readers ignore unknown members, treat `null` as absent, and reject a present member of the wrong type.

| Member | Type | Present for | Meaning |
| --- | --- | --- | --- |
| `v` | integer, 1 | all | Payload version |
| `kind` | string | all | Equal to the envelope's `kind` |
| `server` | string, at most 128 code points | all | The app's own reference for the server, from `registerDevice` |
| `exp` | integer | all | Equal to the envelope's `exp` |
| `pending` | integer ≥ 0 | all | Pending permission requests and forms on the server |
| `sessionID` | string | permission, question, finished, failed; resolved when known | The session that raised the event |
| `rootSessionID` | string | permission, question, finished, failed; resolved when known | The root of its family; equal to `sessionID` for a root session |
| `title` | string | when known | Session title |
| `project` | string | when known | Project folder name |
| `requestID` | string | permission, question, resolved | `per_…` or `frm_…` |
| `action` | string | permission | Permission action |
| `summary` | string | when there is one | The resources joined with newlines (permission), the first question (question) or the error message (failed) |
| `options` | array of strings | question | Option labels of the first field |
| `risk` | string | permission | `low`, `elevated` or `high`; readers treat any other value as `high` |
| `digest` | string | permission, question | See "Digest" |
| `freeText` | boolean | question | The form has exactly one field, of type `string`, that accepts typed text (no options, or `custom: true`) |
| `reply` | string | resolved | `once`, `always` or `reject` for a permission; `answered` or `cancelled` for a form; `cancelled` for a permission that ended without an answer (Stop, deleting the session, or the location shutting down) |

### Limits and truncation

Identifiers (`server`, `sessionID`, `rootSessionID`, `requestID`, `digest`) are never shortened; a `server` reference over 128 code points is an error. Display text is cut by Unicode code points (Swift `unicodeScalars`, JavaScript string iteration), never inside a code point. A cut string keeps its first `limit − 1` code points and ends with `…` (U+2026), so it is exactly `limit` code points long; a limit of 0 removes the member.

1. Caps: `title` 100, `project` 60, `action` 64, `summary` 300, `options` the first 8 labels, each label 40.
2. The serialized plaintext must be at most 2,047 bytes, so that it and the padding marker fit the largest bucket. If the capped payload is longer, the first of these that fits is used:
   1. the capped payload with `summary` cut to the longest length that fits;
   2. without `options`, with `summary` cut to fit;
   3. without `options` and `summary`, with `title` cut to fit;
   4. without `options`, `summary` and `title`, with `project` cut to fit.
3. If none fits, nothing is sent.

"Longest length that fits" is the largest length below the current one whose serialization fits; a binary search finds it because shorter cuts never serialize longer. Only the plugin builds payloads; `vectors/payload.json` covers the rules.

### Padding

ISO/IEC 7816-4: the plaintext, one `0x80` byte, then `0x00` bytes up to the smallest of 512, 1,024 and 2,048 bytes that holds the plaintext plus the marker. Unpadding requires a bucket-sized input whose last non-zero byte is `0x80`, and returns the bytes before it.

## Digest

The app approves a request from a notification only if the request it fetches from the server again still has the digest it was shown. The digest is the lowercase hex SHA-256 of the UTF-8 bytes of the RFC 8785 (JCS) serialization of a projection of the server's JSON. Members outside the projection, such as `metadata`, `source` and `message`, are not covered.

**Permission request** (`Permission.Request`, from `permission.asked` or `GET /api/session/{sessionID}/permission/{requestID}`):

```json
{ "requestID": id, "sessionID": sessionID, "action": action, "resources": resources, "save": save }
```

`resources` and `save` keep the server's order. An absent or `null` `save` is `[]`.

**Form** (`Form.Info` from `form.created`, or `Form.Detail` from `GET /api/session/{sessionID}/form/{formID}`):

```json
{ "formID": id, "sessionID": sessionID, "title": title,
  "fields": [ { "key": key, "type": type, "title": title, "description": description,
                "options": [ { "value": value, "label": label } ] } ] }
```

Fields keep the server's order. An absent or `null` field `title` or `description` is `""`, and absent or `null` `options` are `[]`. Option descriptions, defaults, limits, conditions and the `url` of an external field are not covered.

The projection contains only strings, arrays and objects, so canonicalization reduces to key order and string escaping:

- object members are sorted by the UTF-16 code units of their names (so U+1F600 sorts before U+E000);
- strings escape `"`, `\` and U+0000–U+001F only, using `\b`, `\t`, `\n`, `\f`, `\r` or lowercase `\u00xx`, and keep every other character, including U+007F, U+2028 and non-ASCII text, as UTF-8;
- there is no insignificant whitespace;
- a lone surrogate, which JSON can carry but no Swift string can hold, is a non-issue for agreement: TypeScript replaces it with U+FFFD before hashing (strict RFC 8785 would reject it), while Swift's `JSONDecoder` refuses the whole document, so the app never reads such a request and never computes a digest to compare. It fails closed rather than disagreeing.

Text is not normalized: `café` written with U+00E9 and with `e` + U+0301 have different digests, as they are different server data.

## Risk rules

`risk-rules.json` ports the app's original `PermissionRisk` rules exactly and adds the high-risk cases ARCHITECTURE §4.6 names that they lacked: `external_directory` as an explicit rule (the original rules already rated it high as an unknown action) and force-push in any position after `git`, such as `git -C repo push --force`, which the original `git\s+push` missed. It also bounds the cost of a request: joined resources longer than `limits.maxLength` UTF-16 code units (8,192; JavaScript `length`, Swift `utf16.count`) are rated by `limits.rule` (`too-long`, high) before any pattern runs.

Classification of `(action, resources)`:

1. Find the action rule whose `actions` contains `action` (exact, case-sensitive). If none, use `default`.
2. If the rule has `escalate` patterns, join `resources` with `\n`, lowercase the result with the Unicode default mapping (Swift `lowercased()`, JavaScript `toLowerCase()`), and return the first pattern that matches.
3. Otherwise return the rule's own tier. The result is the tier and the deciding rule's `id`.

Patterns are written in a portable regular-expression dialect that ICU (`NSRegularExpression`, no options) and ECMAScript (`RegExp`, no flags) evaluate identically, so Swift and TypeScript classify identically:

- `{name}` expands to the macro of that name before compiling. `{bow}` and `{eow}` are ASCII word boundaries (`(?<![a-z0-9_])`, `(?![a-z0-9_])`), `{ws}` is the union of ECMAScript's `\s` and ICU's `\s` (ECMAScript's set plus U+0085), `{line}` any character except `\n`, `\r`, U+2028 and U+2029, `{cmd}` the same without `;`, `&` and `|`, and `{tok}` a `{cmd}` character that is not `{ws}`.
- Quantified parts never overlap their neighbours, so no input makes a pattern backtrack catastrophically: a repeated group is `{ws}+{tok}+`, which has one way to split any text, and a token that must not be consumed is excluded with a lookahead. Force-push stops at the first `push` after `git` and never scans past a later `git`, and download-to-pipe never scans past a later `curl` or `wget` (the last one before a pipe matches anyway), so the time is linear in the text, not in the number of starting tokens times its length. `test/risk-rules.test.ts` times every rule on adversarial inputs at the length cap.
- No `\b`, `\s`, `\w`, `\d`, `.`, anchors, flags, backreferences or Unicode properties; lookbehinds hold a single class; literals are printable ASCII and other characters are written as `\uXXXX`. `test/risk-rules.test.ts` enforces this.

These spellings match everything the original ICU patterns matched, and a few more inputs: a command touching a non-ASCII letter, such as `ärm` (ICU treats `ä` as a word character, so its `\b` found no boundary), whitespace that ECMAScript counts and ICU does not (U+FEFF), and `curl … | …` across U+0085, at which ICU's `.` stops but `{line}` does not. ICU's `\s` matches U+000B and U+0085, so both are in `{ws}`. Lowercasing differences between the platforms (only Greek final sigma) cannot change a result, because every pattern is ASCII apart from the whitespace set.

## Vectors

All keys come from fixed labels in the generator; nothing in `vectors/` is a real secret. `node scripts/generate-vectors.ts --check` and the Vitest suite fail if a committed vector differs from a fresh generation.

| File | Contents |
| --- | --- |
| `envelope.json` | A keyring, valid envelopes for every kind and bucket with their AAD and exact plaintext, and 28 rejections that each change one thing: every AAD field, the version, the sender key, the key ID, expiry, flipped, truncated and swapped ciphertext, a flipped `enc`, bad padding, a bad payload, kind and expiry mismatches, integers beyond ±(2⁵³ − 1), and malformed fields |
| `digest.json` | Permission and form inputs as the server sends them, their canonical projection and digest: Unicode, control characters, member order, extra members, empty arrays, and absent, empty and `null` `save` (all equal) |
| `jcs.json` | Canonicalization of literals, integers, empty containers, nesting, ASCII and UTF-16 member order, escapes and Unicode |
| `padding.json` | Padding at and across every bucket boundary, an oversized input, and valid and invalid unpadding |
| `payload.json` | Drafts and their fitted payloads, exact plaintext, size and bucket, including oversized and control-character text |
| `risk.json` | Classification of every rule, the cases of the original Swift rules and the boundaries of each pattern |
| `rfc9180-a23.json` | The RFC 9180 test vector for this exact suite in auth mode (Appendix A.2.3), which checks both HPKE implementations independently of the generator |
