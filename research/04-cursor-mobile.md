# Cursor's mobile experience: feature inventory

Research date: 2026-10-15. Prepared for the opencode native iOS/iPadOS client project.

## 0. How to read this report

- **Primary sources** are Cursor-owned pages: the changelog, docs, release notes, blog, App Store listing, and forum posts written by Cursor staff. Press articles, review sites and forum posts by users are labelled as third-party or user reports.
- **Verification tags.** The first pass tagged claims it could not confirm in a page it actually opened as "unverified". A second pass on 2026-10-15 resolved every one of those tags: confirmed claims now carry a source, corrected claims end with "(corrected 2026-10-15)", and anything still without public evidence carries an "unconfirmed" tag (with the reason and what was tried) or a "needs browser" tag (with the URL to open). The log is in "Verification pass (2026-10-15)" at the end. Nothing in this report is a guess presented as fact.
- **What I did not do.** I did not run the app. I found no independent long-form hands-on review of it. The "hands-on" signal in this report comes from App Store reviews, forum threads, a Product Hunt thread and a couple of social posts.
- **Tooling caveats.** The web-search budget ran out late in the session, so some leads (Hacker News and Reddit threads, anything published after 2026-10-13) were not followed. Many pages were read through a summarising fetch tool, so numbers taken from the App Store review feed were approximate; the 2026-10-15 pass recomputed them from the raw feed (section 8, item 9).
- Every claim carries a URL. Dates are ISO format and follow the dates printed on the cited page.
- Cursor product names changed a lot in 2025 and 2026. "Background Agents" were renamed "Cloud Agents" in Cursor 2.0 ([changelog 2.0](https://cursor.com/changelog/2-0)). "Agents Window" is the agent-first desktop interface that arrived with Cursor 3 ([Cursor 3 post](https://cursor.com/blog/cursor-3)).

## 1. Executive summary

1. **Cursor now has a native iPhone and iPad app, not only a PWA.** "Cursor for iOS" went into public beta on 2026-06-29 on all paid plans ([blog](https://cursor.com/blog/ios-mobile-app), [changelog 3.9](https://cursor.com/changelog/ios-mobile-app), [App Store](https://apps.apple.com/us/app/cursor/id6767085653)). iPad layout, an Inbox and full pull-request review followed on 2026-07-29 ([changelog](https://cursor.com/changelog/ipad)). The app requires iOS or iPadOS 26.0 or later and is English only. There is no Android app; Android users get the web app as a PWA ([docs](https://cursor.com/docs/cloud-agent/mobile), [help](https://cursor.com/help/ai-features/mobile-app)).
2. **It is a supervise-and-review client, not an IDE.** There is no editor, terminal or file browser; changed files appear only in a diff view ([docs](https://cursor.com/docs/cloud-agent/mobile)).
3. **One backend, every surface.** The app uses the same backend as cursor.com/agents and the desktop Agents Window, so agents started anywhere show up everywhere, and mobile-started agents are tagged `source: iosApp` ([docs](https://cursor.com/docs/cloud-agent/mobile)).
4. **Three places an agent can run:** a Cursor-hosted cloud VM, a Team Pool, or one of your own machines ("My Machines"). Separately, **Remote Control** lets the phone drive an agent on your own computer ([docs](https://cursor.com/docs/cloud-agent/mobile), [Oct 6 changelog](https://cursor.com/changelog/remote-control-local-agents)).
5. **The review-to-merge loop fits in the app:** changed files, commits, checks, approvals, deployments, comments, reviewer changes, asking the agent to fix a failing check or resolve comments, squash merge, mark ready, update branch, auto-merge, publish and close ([docs](https://cursor.com/docs/cloud-agent/mobile)). The big missing piece is line-anchored comments that the agent acts on ([forum](https://forum.cursor.com/t/mobile-code-review-for-cursor-changes/166889)).
6. **Evidence-first verification.** Cloud agents run their own desktop and return videos, screenshots and logs so you can judge work without checking out the branch ([capabilities docs](https://cursor.com/docs/cloud-agent/capabilities)).
7. **Notifications:** push notifications plus Live Activities on the lock screen and Dynamic Island for up to eight agents ([docs](https://cursor.com/docs/cloud-agent/mobile)). Note the conflict in section 8: since the week of 2026-08-31 Cloud Agents no longer send "turn finished" pushes, only question and approval pushes ([release notes RSS](https://cursor.com/docs/release-notes/rss.xml)).
8. **Input:** voice dictation with live captions, screenshot markup with pinned comments, camera, any file type, Apple Pencil on iPad ([release notes](https://cursor.com/docs/release-notes/mobile), [iPad changelog](https://cursor.com/changelog/ipad)).
9. **Phone-friendly entry points outside the app:** Slack (`@Cursor`), Linear (delegate an issue), GitHub (`@cursor` in PR or issue comments, Bugbot), Jira and Microsoft Teams ([Slack docs](https://cursor.com/docs/integrations/slack), [Linear docs](https://cursor.com/docs/integrations/linear), [cloud agent docs](https://cursor.com/docs/cloud-agent), [Jira changelog](https://cursor.com/changelog/page/6), [Teams changelog](https://cursor.com/changelog/page/7)).
10. **Pricing gate:** you need a plan that includes Cloud Agents: Premium, Super, Ultra, Teams or Enterprise on the new "X Subscription", or legacy Start, Pro, Pro+, Ultra. The $8 Plus tier and Free cannot start runs ([docs](https://cursor.com/docs/cloud-agent/mobile), [pricing](https://cursor.com/pricing), [help](https://cursor.com/help/account-and-billing/pricing)).
11. **Biggest user complaints:** iOS 26-only, no Android, Remote Control reliability and discoverability, approvals not reaching the phone, no inline diff comments, no settings screen, and billing confusion after the move to the X Subscription (section 10).

### 2.1 Corporate and pricing context

- SpaceX (Space Exploration Technologies Corp.) signed a merger agreement for Anysphere (Cursor's maker) on 2026-06-16, at an implied equity value of $60.0 billion paid in SpaceX Class A stock, and completed the merger on 2026-08-14. #### 3.1.3 Feature inventory

Each feature lists what it does, UX specifics, limits and plan notes, and launch date.

**F1. Agent inbox (home screen)**

- *What it does:* One list of your agents across cloud runs, Projects, and (through Remote Control) agents on your computers, including ones started on web, desktop, Slack, GitHub or Linear. The Jul 29 changelog describes it as one place to see what is in progress, what needs attention and which PRs are in review ([changelog](https://cursor.com/changelog/ipad)). Agents started on mobile can be filtered on each surface ([help](https://cursor.com/help/ai-features/mobile-app)).
- *UX specifics:*
  - Sections for Pinned, Drafts and Projects. On iPhone you tap a section header to collapse or expand it, and the choice carries to the iPad sidebar ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Pull down to refresh ([help](https://cursor.com/help/ai-features/mobile-app)).
  - Cache-first: it reads local data so the inbox and conversations open fast, then syncs when the connection returns ([docs](https://cursor.com/docs/cloud-agent/mobile)).
  - An agent waiting on MCP sign-in shows as "Needs Attention" in the inbox and on the Live Activity until you tap Skip or Authenticate ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Project rows show a loader while the coordinator runs and update when workers finish, fail or restart ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Computers you can remote-control appear grouped; an Add Workspace action pins or unpins workspaces ([staff reply](https://forum.cursor.com/t/cursor-mobile-and-remote-control-hard-to-use/171650)).
  - Your profile is at the upper left; the app version is at the bottom of that sheet ([help](https://cursor.com/help/ai-features/mobile-app)). The 1.9.0 fixes also mention a profile sheet that shows charts while stats load and a "Customize" sheet with sections named Show and Agent Properties ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)). Cursor's help calls the profile sheet "the app's settings" ([help](https://cursor.com/help/ai-features/mobile-app)), so the app does have a minimal settings sheet; the "no settings menu" complaint in section 10 is about missing controls (skills, rules, MCPs, appearance), not about the absence of any sheet (corrected 2026-10-15). What the Customize sheet controls is still undocumented [unconfirmed: not described in the docs, help, release notes or forum (searched "ios customize sheet"); would need the app].
  - Agents can be renamed; the composer shows quick-action pills and its placeholder switches between new-agent and follow-up text; pill animations fall back to a plain fade when Reduce Motion is on ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
- *Limits:* A computer's workspace appears only if Remote Control is on for that computer and the workspace is open; showing all local editor chats automatically "isn't possible yet" ([staff reply](https://forum.cursor.com/t/cursor-mobile-and-remote-control-hard-to-use/171650)). A user review says recent agents are hard to find unless pinned ([App Store feed](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json)).
- *Launch:* agent list at 1.0.0 (2026-06-29); "Inbox" called out as new on 2026-07-29; Projects section 2026-09-22.

**F2. Starting an agent**

- *What it does:* You choose a repository and branch, write a task, and send it. Cursor says it works like the desktop app: pick a repo, pick any frontier model, dictate or type, use slash commands ([blog](https://cursor.com/blog/ios-mobile-app), [docs](https://cursor.com/docs/cloud-agent/mobile)).
- *UX specifics:*
  - **Where it runs, per run:** a Cloud machine, a Team Pool, or one of My Machines ([docs](https://cursor.com/docs/cloud-agent/mobile)).
  - **Repo and branch:** the repo picker shows only source control connected on the web (GitHub or GitLab; Bitbucket and Azure DevOps were added in July). If it is empty, connect on cursor.com, then pull down on the inbox; if it is empty on the web too, the integration is not connected ([help](https://cursor.com/help/ai-features/mobile-app), [iPad changelog](https://cursor.com/changelog/ipad)). The workspace picker has a Recents list that hides unavailable repos and environments ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - **Mode:** Plan mode is available when launching ([release thread](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417)). There is no Ask mode: staff said on 2026-07-15 that the iOS app offers only Plan and Agent modes (and that Cloud Agent modes did not exist on the web at all), and a user was still asking for Ask mode on iOS on 2026-09-13 ([forum](https://forum.cursor.com/t/ask-mode-in-cloud-agents/165658)) (corrected 2026-10-15).
  - **Model:** see F13.
  - **Commands and tools:** slash commands, skills and automations behave on mobile as they do locally, in the CLI and on the web; you choose MCP servers per run (including the Slack MCP), but add and manage them on the web ([docs](https://cursor.com/docs/cloud-agent/mobile)). A staff reply says MCP servers are managed from the iOS context pane after being configured at cursor.com/agents ([bug thread](https://forum.cursor.com/t/cursor-ios-bugs/164391)).
  - **Projects:** on iPhone, a "New Project" row starts a Project from a name with optional repo, branch and model; it is hidden if a team admin disables Projects ([1.10.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - **Repo-less starts:** "Start from scratch" in the repo picker creates an Origin repo in the background (announced for the web and Cloud Agents on 2026-08-27, [changelog](https://cursor.com/changelog/start-from-scratch)). The iOS blog lists repo-less chats as upcoming ([blog](https://cursor.com/blog/ios-mobile-app)). Whether the iOS picker already offers "Start from scratch" is [unconfirmed: the 2026-08-27 changelog does not name a surface, the iOS release notes for 1.9.0 to 1.12.0 do not mention it, and a forum search found nothing; would need the app]. A Project, though, can be started on iPhone without a repo, because the repo is optional ([1.10.0 notes](https://cursor.com/docs/release-notes/mobile)).
- *Limits and plan:* paid plan with Cloud Agents; Privacy Mode (not Legacy) is required, and the app prompts you to switch (see section 7.1) ([docs](https://cursor.com/docs/cloud-agent/mobile)). Every run uses the model's maximum context window ([docs](https://cursor.com/docs/cloud-agent/mobile)).
- *Launch:* 2026-06-29. Multi-team support and Bitbucket and Azure DevOps arrived with a later build (1.3.0, dated 2026-07-15 on the App Store; the changelog announces them on 2026-07-29) (corrected 2026-10-15). Per-run worker choice was there from launch: the iOS docs archived on launch day already say "Pick a worker for each run: a Cloud machine, a Self-Hosted Pool, or one of My Machines", and the pool option was later renamed Team Pool ([docs on 2026-06-29](https://web.archive.org/web/20260629172104/https://cursor.com/docs/cloud-agent/mobile)). A user reported starting new chats on his own machine from the phone on 2026-06-30 after running `agent worker start` ([release thread](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417/44)) (corrected 2026-10-15).

**F3. Following along and steering a running agent**

- *What it does:* Live chat stream, follow-ups to a running agent, and subagent cards that open the child transcript ([docs](https://cursor.com/docs/cloud-agent/mobile)).
- *UX specifics:*
  - In-progress labels read "Working" and "Thinking" ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)). Ordinary agent chats evidently carry "Worked" and thinking sections, because the 1.12.0 notes say Project coordinator chats hide them; those coordinator chats instead show a live status line such as the current step, running commands, messaging an agent, or writing a reply ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - A new agent's prompt stays pinned to the top when the reply starts; loading dots show activity ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Scrolling up loads earlier messages automatically and keeps your place; dragging the scroll indicator scrubs through long chats ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Tapping a cursor.com/agents link inside a chat, including a subagent link, opens that agent in the app; shared links open the chat directly ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - When a cloud agent shares its running app, the chat shows a preview card (screenshot, title, description) and a Preview button that opens the agent's desktop view on cursor.com ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Streaming survives bad networks: the stream reconnects after network changes, pauses in the background, then catches up ([help](https://cursor.com/help/ai-features/mobile-app)).
  - Very large edited files show "File too large to preview" with a Copy action, and large-edit chats stay responsive ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
  - Marketing screenshots show a "Follow up..." composer and a list of recent tasks each marked "Working" ([mobile page](https://cursor.com/mobile)).
- *Steering semantics:* On desktop and cloud agents, you can send a message while the agent works without interrupting it; the message waits for the agent's next tool call. Press Send, or press Enter twice ([changelog 2026-08-19](https://cursor.com/changelog/08-19-26)). GitHub `@cursor` comments queue into a running agent, and you can click "Send now" in the follow-up queue on cursor.com/agents ([forum](https://forum.cursor.com/t/default-github-cursor-agent-comments-to-send-immediately-not-queue/167668)). On iOS, staff said on 2026-09-15 that a message sent while the agent runs goes into a queue shown as a "Queued" pill above the composer; each queued message has a "Send now" button that interrupts the current step and delivers it, and tapping Stop while something is queued stops the run and sends the first queued message. - *Launch:* 2026-06-29. A reviewer asked for subagent visibility on 2026-07-06 and the developer replied on 2026-07-07 that it was fixed ([App Store](https://apps.apple.com/us/app/cursor/id6767085653)).

**F8. Remote Control (directing agents on your own computer)**

Two flows are documented, and Cursor's pages do not yet agree on how the second relates to the first.

- *Flow A, "hand off a session" (launched 2026-06-29):*
  1. Use Cursor 3.9.8 or later, in the Agents Window only (not the editor window) ([docs](https://cursor.com/docs/cloud-agent/mobile), [staff reply](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2)).
  2. Turn it on in Settings > Agents. On Teams and Enterprise an admin must enable it first in Dashboard > Cloud Agents > Self-Hosted ([docs](https://cursor.com/docs/cloud-agent/mobile)).
  3. In the agent's input run `/remote-control`, then send your next message; that message performs the handoff ([staff reply](https://forum.cursor.com/t/remote-control-does-not-work-as-expected/170362)).
  4. The session appears in the app inbox. The agent loop runs in Cursor's cloud; every tool call (terminal, file edits, tests, git) runs on your computer, and your repo, secrets and caches stay there ([docs](https://cursor.com/docs/cloud-agent/mobile)).
  5. The computer must stay awake and online. "Keep this computer awake" (Settings > Agents) prevents sleep while plugged in ([docs](https://cursor.com/docs/cloud-agent/mobile)).
  6. Conversion is not lossless: staff say some context appears condensed ([staff reply](https://forum.cursor.com/t/remote-control-does-not-work-as-expected/170362)).
  7. Works with local or Remote SSH workspaces; a Git remote is not required; not available if privacy settings disable cloud data storage ([docs](https://cursor.com/docs/cloud-agent/mobile)).
- *Flow B, pairing (announced 2026-10-06):* download the iOS app and sign in; computers on your account appear automatically; tap your computer and approve the pairing request in the desktop app; your local agents appear as a list; tap one to see what it is doing or message it. Agents stay on the computer and Remote Control does not move them to the cloud or require cloud agents. It is on for everyone except Enterprise orgs, where an admin enables it under Org settings > Security and identity > Remote control. "Keep this computer awake" needs the computer plugged in with the lid open ([changelog](https://cursor.com/changelog/remote-control-local-agents)). A third-party article says you can also start new tasks on the paired computer from the phone ([AlphaSignal](https://alphasignal.ai/news/cursor-ships-remote-control-so-developers-run-local-agents-from-iphone)). The 2026-10-06 entry only says view and message, but Cursor staff had already confirmed that new work can be started on your own computer from the phone: register the machine once (`agent worker start`, or turn on Remote Control in the Agents Window), then pick it when you start an agent on the phone ("new agent → pick your computer under Remote Control") ([staff, 2026-07-31](https://forum.cursor.com/t/enable-local-agents-visibility-on-ios-app/166896/4), [staff, 2026-08-21](https://forum.cursor.com/t/cant-make-remote-control-work/169050/5)).
- *Starting brand-new work on your own machine from the phone:* register the machine as a "My Machine" with the CLI (`agent login`, `agent worker start`), then pick it under "Run on". The worker opens an outbound connection only, so no inbound ports are needed ([My Machines docs](https://cursor.com/docs/cloud-agent/self-hosted/my-machines)). The iOS docs list My Machines as a per-run worker choice ([docs](https://cursor.com/docs/cloud-agent/mobile)).
- *Other limits:* tool calls cannot run while the computer is asleep or offline ([docs](https://cursor.com/docs/cloud-agent/mobile)). When Remote Control is turned off, the phone now shows "disabled" instead of a generic error ([RSS, week of Oct 5](https://cursor.com/docs/release-notes/rss.xml)).

## 4. Integrations people use from a phone

### 4.1 Slack

- **Launch:** 2025-06-12 (Cursor 1.1); to-do lists stream into Slack from 2025-07-03 (1.2); big update on 2026-07-17 ([changelog p15](https://cursor.com/changelog/page/15), [Slack update](https://cursor.com/changelog/slack-improvements)).
- **Setup:** a Slack workspace admin installs the Cursor app; then you connect a repo provider and default repo, enable usage-based pricing and confirm privacy settings. Cloud Agents require Privacy Mode, not Legacy ([Slack docs](https://cursor.com/docs/integrations/slack)).
- **Starting an agent:** mention `@cursor` with a prompt. Cursor tries to detect the repo, model, base branch or named multi-repo environment from the message and from your recent activity, and it reads the whole thread as context ([Slack docs](https://cursor.com/docs/integrations/slack)).
- **Options** can be written in natural language ("with opus", "in acme/backend") or inline: `repo=`, `env=`, `branch=`, `model=`, `autopr=false`, `worker=` or `machine=` (one of your own machines), `pool=`, `self_hosted=`, `channel=` ([Slack docs](https://cursor.com/docs/integrations/slack)).
- **Commands:** `@Cursor settings` (channel default repo and defaults), `@Cursor list my agents`, `@Cursor agent [prompt]` (force a new agent in a thread that already has one), and pool commands for team admins ([Slack docs](https://cursor.com/docs/integrations/slack)). Routing rules map keywords such as "frontend" or "mobile" to repos or environments ([Slack docs](https://cursor.com/docs/integrations/slack)).
- **Progress UX:**
  - Since 2026-07-17 Cursor posts a plan first so you can redirect early, then keeps a short status under the thread; in-message buttons became compact footer links ([Slack update](https://cursor.com/changelog/slack-improvements)). The docs say simple requests skip the plan ([Slack docs](https://cursor.com/docs/integrations/slack)).
  - Status shows as reactions: an hourglass while running, a check mark when done, a cross mark on failure ([Slack docs](https://cursor.com/docs/integrations/slack)).
  - "Open in Cursor" appears when a run starts; completion brings a Slack notification and a link to the PR ([Slack docs](https://cursor.com/docs/integrations/slack)).
  - A three-dot menu on an agent message offers Add follow-up, Switch repository, Delete (stops and archives), View request ID and Give feedback ([Slack docs](https://cursor.com/docs/integrations/slack)).
  - If the task needs another repo mid-run, a "Switch repository" button appears and Cursor resumes where it stopped; it can also read and post in other channels and threads ([Slack update](https://cursor.com/changelog/slack-improvements)).
  - Artifact links unfurl with file name, type and video length; PR links unfurl with a short excerpt ([release notes](https://cursor.com/docs/release-notes)).
- **Follow-ups:** `@Cursor [prompt]` in a thread that already has an agent adds a follow-up; who may do so depends on the admin "team follow-ups" setting ([Slack docs](https://cursor.com/docs/integrations/slack), [settings docs](https://cursor.com/docs/cloud-agent/settings)).
- **Watching over time:** from 2026-08-19 you can ask `@cursor` to check back later (the example is one hour) because agents can subscribe to Slack threads ([changelog](https://cursor.com/changelog/08-19-26)).
- **Limits:** Team Pools need Enterprise; "Display Agent Summary" (diff images and code snippets) can be turned off, separately for external channels ([Slack docs](https://cursor.com/docs/integrations/slack)).
- **Phone angle:** on a phone this is just the Slack app. I found no Cursor-specific Slack mobile UI.

### 4.2 Linear

- **Launch:** 2025-08-21 (Cursor 1.5) ([changelog p14](https://cursor.com/changelog/page/14), [Linear changelog](https://linear.app/changelog/2025-08-21-cursor-agent)).

- **Progress UX:** Cursor shows real-time status in Linear. Delegated issues show in Linear's My Issues view with statuses for working, waiting on input and finished, and you are notified when it needs input or completes ([Linear docs](https://cursor.com/docs/integrations/linear), [Linear changelog](https://linear.app/changelog/2025-08-21-cursor-agent)). The session shows the agent's thoughts, tools and to-dos ([Linear blog](https://linear.app/blog/how-cursor-integrated-with-linear-for-agents)).
- **Follow-ups and PRs:** reply in the agent session or mention `@Cursor`; the agent creates a branch and PR automatically ([Linear docs](https://cursor.com/docs/integrations/linear)). Linear says you can also take over in the Cursor app ([Linear changelog](https://linear.app/changelog/2025-08-21-cursor-agent)).
- **Configuration:** `[repo=...]`, `[branch=...]`, `[model=...]` in descriptions or comments, or parent-child labels such as a `repo` label group; repo is chosen in the order: inline, issue label, project label, dashboard default ([Linear docs](https://cursor.com/docs/integrations/linear)). Triage rules can auto-delegate issues, but Linear needs a human assignee for them to fire ([Linear docs](https://cursor.com/docs/integrations/linear)).
- **Phone angle:** Cursor's Linear docs and Linear's Cursor blog post do not mention mobile ([Linear docs](https://cursor.com/docs/integrations/linear), [Linear blog](https://linear.app/blog/how-cursor-integrated-with-linear-for-agents)), but Linear's changelog says that since 2026-03-12 a delegated agent's session opens in the Linear mobile app with real-time reasoning and past sessions, and agents that support it can be steered with further messages there ([Linear changelog](https://linear.app/changelog/2026-03-12-ui-refresh)). Neither company says anything Cursor-specific about it (corrected 2026-10-15).
- Linear's own interview notes that commenting on every step felt noisy, and that agent summaries should help a reviewer decide quickly ([Linear blog](https://linear.app/blog/how-cursor-integrated-with-linear-for-agents)).

### 4.3 GitHub, Bugbot and pull-request comments

- **Install:** needs Cursor admin plus GitHub org admin; works with GitHub Enterprise Server. The GitHub app asks for permissions that include reading branch protection and required-check rules (to decide whether a PR is mergeable) and reading custom repository roles (so the right merge and review options are shown) ([GitHub docs](https://cursor.com/docs/integrations/github)).
- **Start an agent from a comment:** `@cursor` plus an instruction in a PR or issue comment starts a cloud agent that reads the diff, comment thread and CI and opens a fix PR; staff say it should work on merged or closed PRs, and that putting `@cursor` at the start of the message is sometimes more reliable ([forum, 2026-07-17](https://forum.cursor.com/t/launch-agents-from-pr-comments-including-closed-prs-to-create-a-new-branch-and-fix-follow-up-issues/165956)). Launched 2025-08-06 in Cursor 1.4 ([changelog p14](https://cursor.com/changelog/page/14)). The My Machines docs show the handle `@cursoragent` for GitHub ([docs](https://cursor.com/docs/cloud-agent/self-hosted/my-machines)), while the cloud-agent overview and the Bugbot docs use `@cursor` on GitHub ([cloud agent docs](https://cursor.com/docs/cloud-agent), [Bugbot docs](https://cursor.com/docs/bugbot)). On GitHub, `cursoragent` is a user account named "Cursor Agent" and `cursor` is Cursor's organization, whose GitHub App receives issue and review comment events (`gh api users/cursoragent`, `gh api apps/cursor`). Which handles work where is [unconfirmed: no Cursor page says whether both handles work in every context; testing needs a repo with the app installed].
- **Queueing:** GitHub comments queue into a running agent and run after the current step; Slack messages are delivered immediately. "Send now" in the web follow-up queue forces it ([forum](https://forum.cursor.com/t/default-github-cursor-agent-comments-to-send-immediately-not-queue/167668)).
- **Bugbot:** comment `cursor review` or `bugbot run` on a PR; results are PR comments with "Fix in Cursor" and "Fix in Web" links and a `Cursor Bugbot` check; Autofix can spawn a Cloud Agent to push fixes (new branch or existing branch, max three attempts per PR for the latter) ([Bugbot docs](https://cursor.com/docs/bugbot)). Bugbot launched 2025-06-04; Autofix 2026-02-26 ([changelog p15](https://cursor.com/changelog/page/15), [changelog](https://cursor.com/changelog/02-26-26)).
- **CI auto-fix:** Cloud Agents try to fix CI failures on PRs they create (GitHub Actions only, Teams only), skip when you push or message, and stop after 10 follow-ups; `@cursor autofix off` or `on` toggles it ([capabilities docs](https://cursor.com/docs/cloud-agent/capabilities)).
- **Phone angle:** the Bugbot docs do not cover GitHub's mobile app. In principle the triggers are plain comments that any client can post, but Cursor does not say so, and whether "Fix in Cursor" or "Fix in Web" links hand off cleanly on a phone is [unconfirmed: the Bugbot docs say "Fix in Web" opens cursor.com/agents, and cursor.com's apple-app-site-association file routes /agents and /agents/bc-… links to the iOS app, so on an iPhone with the app installed such a link should open the app; what the app then does with a Bugbot fix link is undocumented and would need a device test] ([Bugbot docs](https://cursor.com/docs/bugbot), [app-site association file](https://cursor.com/.well-known/apple-app-site-association)).

### 4.4 Jira and Microsoft Teams

- **Jira (2026-05-19):** assign a Jira work item to Cursor or mention `@Cursor` in a comment to start a cloud agent; Jira shows updates and the PR link. Needs Cursor admin access and Jira Commercial Cloud with Rovo ([changelog p6](https://cursor.com/changelog/page/6)).
- **Microsoft Teams (2026-05-11):** mention `@Cursor` in a channel; Cursor picks the repo and model, reads the thread and creates a PR ([changelog p7](https://cursor.com/changelog/page/7)).

### 4.5 Automations and subscriptions (agents that act without a prompt)

- **Automations (2026-03-05):** always-on cloud agents triggered by schedules or events from Slack, Linear, GitHub, PagerDuty, Sentry and webhooks; a Slack emoji trigger and the `/automate` skill arrived 2026-06-18; results can go to Slack, PR comments, reviewers or new PRs ([changelog p10](https://cursor.com/changelog/page/10), [changelog p4](https://cursor.com/changelog/page/4), [Automations docs](https://cursor.com/docs/cloud-agent/automations)).
- **Subscriptions (2026-08-19):** an agent ends its turn, waits for an event (PR comments, reviews and CI; Slack replies; Linear issue changes; timers) and resumes in the same conversation. Agents automatically subscribe to PRs they create. Subscriptions last at most 180 days ([changelog](https://cursor.com/changelog/08-19-26), [capabilities docs](https://cursor.com/docs/cloud-agent/capabilities)).
- **On the phone:** the iOS docs say automations work on mobile the same way they do locally, but configuration lives on the web, and a user has requested an Automations tab in the app ([iOS docs](https://cursor.com/docs/cloud-agent/mobile), [forum list](https://forum.cursor.com/t/cursor-ios-desperately-needs-love/173832)).

### 4.6 API and SDK (how a third-party client could talk to Cursor)

- The Cloud Agents API (v1, public beta) models a durable **agent** with per-prompt **runs**. `POST /v1/agents` launches (repo, model, `mode` of agent or plan, MCP servers, `autoCreatePR`), `POST /v1/agents/{id}/runs` sends a follow-up, one run can be active at a time (`409 agent_busy`), cancel is final, and artifacts download through presigned URLs valid for 15 minutes ([API docs](https://cursor.com/docs/cloud-agent/api/endpoints)).
- Streaming is server-sent events with types `status`, `assistant`, `thinking`, `tool_call`, `interaction_update`, `heartbeat`, `result`, `error` and `done`; clients resume with `Last-Event-ID` and get `410 stream_expired` after the retention window ([API docs](https://cursor.com/docs/cloud-agent/api/endpoints)). The API was reworked around this model with the SDK launch on 2026-04-29 ([changelog p8](https://cursor.com/changelog/page/8)).

## 5. How mobile ties into the desktop IDE

### 5.1 The Agents Window is the hub

- Cursor 3 (2026-04-02) introduced the Agents Window: a multi-workspace, agent-first interface beside the classic editor. Its sidebar lists all local and cloud agents, including ones started from mobile, web, desktop, Slack, GitHub and Linear ([Cursor 3 post](https://cursor.com/blog/cursor-3)). It became generally available with Cursor 3 ([Agents Window docs](https://cursor.com/docs/agent/agents-window)).
- Features only in the Agents Window: multi-workspace, a diffs view for committing and managing PRs, parallel cloud agents reachable from phone, web, Slack, GitHub and Linear, easier local/cloud handoff, cloud subagents (`/in-cloud`, `/autopilot`), and UI-native worktrees ([Agents Window docs](https://cursor.com/docs/agent/agents-window)). Remote Control also needs it ([docs](https://cursor.com/docs/cloud-agent/mobile)).
- Useful supporting features: tiled layout and upgraded voice in 3.1 ([changelog p9](https://cursor.com/changelog/page/9)); Compact, Balanced and Detailed chat verbosity in 3.4 ([changelog p7](https://cursor.com/changelog/page/7)); side chats with `/side` and `/btw` plus conversation search in 3.11 ([changelog](https://cursor.com/changelog/side-chat)); a "Run on" picker (Cloud, This Computer, Remote Machines) and a repo and branch picker redesign in 3.11 ([changelog](https://cursor.com/changelog/side-chat)).
- Links from cursor.com/agents, Slack, Linear, Teams or "Copy Deep Link" open that agent in the Agents Window even if you never opened it before (3.23); "Open in Cursor" links open it there when the editor has focus (3.24); unread agents appear in the menu bar and Dock menus (3.24) ([release notes](https://cursor.com/docs/release-notes)).

## 7. End-to-end flows

These flows are assembled from the sources cited in each step. Where a control name is not documented I say so instead of guessing.

### 7.1 Onboarding and authentication

**Done on the web first (the app cannot do these):**

1. **Account and plan.** Sign up at cursor.com and choose a plan that includes Cloud Agents. Free accounts can sign in to the app but cannot start runs ([help](https://cursor.com/help/ai-features/mobile-app)).
2. **Connect source control.** GitHub (admin on both the Cursor team and the GitHub org), GitLab, Bitbucket Cloud or Azure DevOps; or skip it with "Start from scratch" backed by Cursor's Origin host ([cloud agent docs](https://cursor.com/docs/cloud-agent), [GitHub docs](https://cursor.com/docs/integrations/github), [changelog](https://cursor.com/changelog/start-from-scratch)). The app's repo picker only shows what is connected on the web ([help](https://cursor.com/help/ai-features/mobile-app)).
3. **Create a cloud environment.** The recommended path is agent-led setup, under 10 minutes, with a shared terminal you can watch; it creates the first Build and saves the environment when the Build succeeds. The manual path is a Dockerfile referenced from `.cursor/environment.json`. Add secrets in the dashboard and start a new agent afterwards, since secrets are injected at agent start ([setup docs](https://cursor.com/docs/cloud-agent/setup), [cloud agent docs](https://cursor.com/docs/cloud-agent)). Builds make cloud agents start about 3x faster ([changelog 2026-08-13](https://cursor.com/changelog/08-13-26)).
4. **Spend settings.** Slack and Linear setup both require enabling usage-based pricing, and the cloud-agent docs say you are asked to set a spend limit on first use ([Slack docs](https://cursor.com/docs/integrations/slack), [Linear docs](https://cursor.com/docs/integrations/linear), [cloud agent docs](https://cursor.com/docs/cloud-agent)).
5. **MCP servers, rules, skills, automations** are configured on the web; you only pick MCP servers per run on the phone ([iOS docs](https://cursor.com/docs/cloud-agent/mobile)).

**On the phone:**

1. Install "Cursor" from the App Store (iOS or iPadOS 26.0 or later) ([App Store](https://apps.apple.com/us/app/cursor/id6767085653)).
2. Sign in with your Cursor account; if your organization requires SSO you sign in through it ([docs](https://cursor.com/docs/cloud-agent/mobile)). Cursor's web sign-in page offers email plus "Continue with" buttons for Google, GitHub, Apple, Grok and X (checked in a browser on 2026-10-15 at https://authenticator.cursor.sh/, which returns a Cloudflare 403 to curl and WebFetch); Cursor's Grok Bot help also describes a "Sign in with Grok" choice ([help](https://cursor.com/help/grok-bot/sign-in)). The in-app iOS sign-in screen itself was not checked, because that needs a device. A review reports "Grok login" broken on 2026-09-08, another reports being unable to sign in on 2026-09-29, and a forum user could not log in or connect GitHub on 2026-06-30 ([App Store feed](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json), [forum](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2)).
3. **Privacy Mode gate.** Cloud Agents need cloud data storage. If you are on Privacy Mode (Legacy) you cannot start agents on mobile until you switch. On first use Cursor prompts you; tap Update, then confirm Switch to Privacy Mode. You cannot switch back. Cursor says it never trains on your code and keeps it only to run the agent ([docs](https://cursor.com/docs/cloud-agent/mobile)). A user refused the change on 2026-07-03 and a third-party reviewer called it a forced, irreversible downgrade ([forum](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2), [review](https://baeseokjae.github.io/posts/cursor-mobile-app-review-2026/)).
4. Pick a repository and branch. If the list is empty: connect GitHub or GitLab on cursor.com, pull down on the inbox, and if repos show on the web but not in the app, sign out and back in ([help](https://cursor.com/help/ai-features/mobile-app)).
5. Optionally allow Live Activities in iOS Settings under Cursor ([help](https://cursor.com/help/ai-features/mobile-app)).
6. Optionally set up Remote Control (section 3.1.3, F8). On Teams and Enterprise an admin must enable it first ([docs](https://cursor.com/docs/cloud-agent/mobile)).
7. If you need to report a bug, Cursor asks for device and iOS version, the app version (profile sheet footer) and the background composer ID of any agent involved, found on cursor.com/agents; staff mention IDs beginning with "bc-" ([help](https://cursor.com/help/ai-features/mobile-app), [staff reply](https://forum.cursor.com/t/remote-control-does-not-work-as-expected/170362)).

### 7.2 Starting an agent from the phone

1. Open the app and start a new agent. The sources I opened do not name the control; the 1.9.0 notes say the composer placeholder switches between new-agent and follow-up text, and a "New Project" row is documented for Projects ([release notes](https://cursor.com/docs/release-notes/mobile)).
2. Choose the workspace: repository and branch, or a multi-repo environment, or a computer's workspace. The picker has a Recents list ([docs](https://cursor.com/docs/cloud-agent/mobile), [release notes](https://cursor.com/docs/release-notes/mobile)).
3. Choose where it runs: Cloud machine, Team Pool or My Machines ([docs](https://cursor.com/docs/cloud-agent/mobile)).
4. Choose a model (any cloud-agent model, including Auto) and optionally Plan mode ([docs](https://cursor.com/docs/cloud-agent/mobile), [forum](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417)).
5. Add input: type or dictate; attach photos, camera shots, files or an annotated screenshot; use slash commands and skills; pick MCP servers for this run ([docs](https://cursor.com/docs/cloud-agent/mobile)).
6. Send. A cloud agent first sets up its environment, installs dependencies and runs updates, which takes time on web and mobile alike ([help](https://cursor.com/help/ai-features/mobile-app)). The agent appears in the inbox as "Working".
7. Leave the app. The agent continues in the cloud, a Live Activity shows progress, and a push arrives if it needs you ([blog](https://cursor.com/blog/ios-mobile-app), [docs](https://cursor.com/docs/cloud-agent/mobile)).

Cursor's own suggested use cases: respond to an on-call page, reproduce a customer bug, act on user feedback, kick off a refactor and check back later ([blog](https://cursor.com/blog/ios-mobile-app), [docs](https://cursor.com/docs/cloud-agent/mobile)). A third-party guide advises narrow tasks with clear acceptance criteria ([The Rundown](https://www.therundown.ai/tools/cursor-for-ios)).

### 7.3 Following up mid-run

1. Open the agent from the inbox or from a push, Live Activity or link. The stream catches up after a connection drop ([help](https://cursor.com/help/ai-features/mobile-app)).
2. Type or dictate a follow-up in the composer ("Follow up..."); the docs say you can send follow-ups to a running agent ([docs](https://cursor.com/docs/cloud-agent/mobile), [mobile page](https://cursor.com/mobile)).
3. Semantics from the desktop and cloud harness: a steering message does not interrupt; it waits for the next tool call ([changelog](https://cursor.com/changelog/08-19-26)). After you press Stop, a message you send runs instead of queuing (fix, week of 2026-10-05) ([release notes](https://cursor.com/docs/release-notes)). On the phone, a follow-up sent mid-run is queued; the "Queued" pill above the composer gives each queued message a "Send now" button that interrupts the current step, and Stop sends the first queued message. The desktop's non-interrupting steer is not available on iOS ([staff, 2026-09-15](https://forum.cursor.com/t/cursor-for-ios-mid-run-steer-send-stop-send-parity-not-only-queue/171729)) (corrected 2026-10-15).
4. Open a subagent card to read what a child agent is doing ([docs](https://cursor.com/docs/cloud-agent/mobile)).
5. If the agent needs an MCP sign-in, tap Skip or Authenticate on the card; it stays "Needs Attention" until you do ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
6. For a Project, talk to the coordinator or open any worker agent it started ([Projects docs](https://cursor.com/docs/agent/projects)).
7. Long-running agents (research preview from 2026-02-12 for Ultra, Teams and Enterprise) propose a plan and wait for approval before they start ([blog](https://cursor.com/blog/long-running-agents)); how that approval looks on iOS is [unconfirmed: the iOS docs, release notes and forum say nothing about long-running-agent plan approvals, and the release notes for the week of 2026-08-31 only mention approval pushes in general; would need the app].

### 7.4 Reviewing code

1. Start with evidence: demo video, screenshots, logs, and the preview card if the agent is sharing its running app ([capabilities docs](https://cursor.com/docs/cloud-agent/capabilities), [1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
2. Tap the Changes card in the chat for touched files with highlighted lines and +/- counts ([staff reply](https://forum.cursor.com/t/mobile-code-review-for-cursor-changes/166889)).
3. Open the PR screen: commits, checks, deployments, approvals, comments ([docs](https://cursor.com/docs/cloud-agent/mobile)).
4. Give feedback as a follow-up message; anchored line comments are not supported ([staff reply](https://forum.cursor.com/t/mobile-code-review-for-cursor-changes/166889)). Ask the agent to resolve review comments or fix a failing check ([docs](https://cursor.com/docs/cloud-agent/mobile)).
5. For risky or complex changes, go to the desktop. Third-party guides recommend merging only small low-risk changes from the phone and holding auth, payments, migrations and infrastructure for desktop review ([Learn Cursor](https://www.learncursor.dev/guides/cursor-remote-control), [The Rundown](https://www.therundown.ai/tools/cursor-for-ios)).

### 7.5 Creating and merging pull requests

1. **Creation.** Agents open PRs themselves. In Slack you can turn this off with `autopr=false` ([Slack docs](https://cursor.com/docs/integrations/slack)); in Linear the agent creates a PR when it finishes ([Linear docs](https://cursor.com/docs/integrations/linear)); the API has `autoCreatePR` ([API docs](https://cursor.com/docs/cloud-agent/api/endpoints)). On iOS the chat offers a "View PR Draft" action ([staff reply](https://forum.cursor.com/t/mobile-code-review-for-cursor-changes/166889)). Cloud Agents should open PRs as drafts by default and mark them ready for review only when you ask, per staff on 2026-08-28 ([forum](https://forum.cursor.com/t/have-a-personal-team-settings-to-open-pr-in-draft-mode-by-default/169827)), which fits the app's Mark Ready action ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)) (corrected 2026-10-15). Several PRs from one chat are all reachable ([changelog](https://cursor.com/changelog/ipad)).
2. **Readiness.** Mark ready (works on draft PRs, including ones opened from a link), update the branch, toggle auto-merge ([docs](https://cursor.com/docs/cloud-agent/mobile), [1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
3. **Merge.** Squash merge, publish or close ([docs](https://cursor.com/docs/cloud-agent/mobile)). Merge options follow your repo rules: the GitHub app reads branch protection, required checks and custom roles so the right options appear ([GitHub docs](https://cursor.com/docs/integrations/github)), and a third-party guide says merging works when permissions, checks and approvals allow ([Learn Cursor](https://www.learncursor.dev/guides/cursor-mobile)).
4. **Agent-initiated merges on Origin repos** raise an approval request with the commit subject and message shown in the mobile approval sheet and in Slack ([release notes, week of Sep 7](https://cursor.com/docs/release-notes)).
5. **After the PR exists,** Cloud Agents automatically subscribe to the PRs they create and work them to completion, including fixing CI failures and bot comments ([changelog](https://cursor.com/changelog/08-19-26)); `/babysit` asks a cloud subagent to prepare a PR for merge ([changelog 3.7](https://cursor.com/changelog/cloud-in-agents-window)).

## 9. (a) Patterns worth copying in a native iOS client for a coding agent

Everything here is drawn from the evidence above; my own inferences are marked.

**Architecture and data**

1. **Thin client over a durable session model.** Cursor models a durable agent with per-prompt runs, streams events over SSE with resume (`Last-Event-ID`), and rejects a second concurrent run ([API docs](https://cursor.com/docs/cloud-agent/api/endpoints)). The app mirrors this: the stream reconnects after network changes, pauses in the background and catches up ([help](https://cursor.com/help/ai-features/mobile-app)).
2. **One backend, every surface, tagged by origin.** Sessions started on phone, web, desktop, Slack, GitHub or Linear all appear in one list, and mobile runs carry a `source: iosApp` tag ([docs](https://cursor.com/docs/cloud-agent/mobile)).
3. **Cache-first reads.** Open the inbox and chats from local data, then sync ([docs](https://cursor.com/docs/cloud-agent/mobile)).
4. **Safe sending.** Backgrounding the app right after sending must not show a false error; Cursor had to fix exactly this in 1.12.0 ([release notes](https://cursor.com/docs/release-notes/mobile)). Also persist drafts; a draft-loss bug was reported on launch week ([forum](https://forum.cursor.com/t/cursor-ios-bugs/164391)).

**Home screen**

5. **Inbox as home**, grouped by what needs you: in progress, needs attention, PRs in review, plus Pinned, Drafts and Projects sections that collapse ([changelog](https://cursor.com/changelog/ipad), [release notes](https://cursor.com/docs/release-notes/mobile)). Group local agents under each connected computer and let users pin workspaces ([staff reply](https://forum.cursor.com/t/cursor-mobile-and-remote-control-hard-to-use/171650)).
6. **A first-class "Needs Attention" state** shared by the inbox, the Live Activity and push, fed by questions, approvals and auth requests such as MCP sign-in ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
7. **Live Activities for several sessions**, with state, elapsed time, a "Finished" card and a "+N more" overflow; eight at once in Cursor's case ([help](https://cursor.com/help/ai-features/mobile-app), [mobile page](https://cursor.com/mobile)). Show total run time on long jobs ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
8. **Notify on what is actionable.** Cursor dropped turn-finished pushes for cloud agents to cut noise but kept question and approval pushes ([RSS](https://cursor.com/docs/release-notes/rss.xml)). [Inference] Make this user-configurable, because users complain there are no settings (section 10).

**Conversation view**

9. **Streaming transcript details worth copying:** pin the new prompt at the top when the reply starts; "Working" and "Thinking" labels; collapsed "Worked" sections; a live one-line status for orchestrator chats; auto-load earlier messages without losing place; a draggable scrubber for long chats; a graceful "file too large" state with Copy ([1.9.0 and 1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
10. **Subagent cards that open child transcripts** ([docs](https://cursor.com/docs/cloud-agent/mobile)).
11. **Universal links into the app,** including subagent links, with shared links landing directly on the chat ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
12. **Preview card for a running app** with screenshot, title, description and a button that opens the remote desktop view ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).

**Input**

13. **Voice that lands as editable text,** with a live caption that grays out words still being recognised ([Product Hunt thread](https://www.producthunt.com/p/cursor/cursor-for-ios-2), [1.9.0 notes](https://cursor.com/docs/release-notes/mobile)). Label messages that came from a voice call ([1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
14. **Screenshot markup that carries position:** circles and comments pinned to locations, tap-to-place on iPad, Apple Pencil drawing ([mobile page](https://cursor.com/mobile), [iPad changelog](https://cursor.com/changelog/ipad)). Accept any file type and treat non-images as documents ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
15. **Per-run choices at launch:** where it runs (cloud, pool, own machine), model including Auto, plan mode, MCP servers ([docs](https://cursor.com/docs/cloud-agent/mobile)). Slack's inline `key=value` plus natural-language option syntax is a good model for a command line in a chat box ([Slack docs](https://cursor.com/docs/integrations/slack)).

**Review and merge**

16. **Evidence before diffs.** Lead with artifacts (video, screenshots, logs); Cursor's answer to the worry that phone approvals become rubber stamps is that the diff view is more focused and the artifacts carry the proof ([Product Hunt thread](https://www.producthunt.com/p/cursor/cursor-for-ios-2)).
17. **A "Changes" card inside the chat** that opens a file list with +/- counts, and a large-diff fallback that lists every file with line counts ([staff reply](https://forum.cursor.com/t/mobile-code-review-for-cursor-changes/166889), [1.12.0 notes](https://cursor.com/docs/release-notes/mobile)).
18. **A PR cockpit that mirrors server rules:** read branch protection and required checks so only valid merge actions appear; offer squash, auto-merge, update branch, mark ready, change reviewers, and let the user ask the agent to fix a failing check or resolve review comments ([GitHub docs](https://cursor.com/docs/integrations/github), [docs](https://cursor.com/docs/cloud-agent/mobile)).
19. **Approval sheets that show exactly what will happen,** such as the commit subject and message of an agent-initiated merge ([release notes, week of Sep 7](https://cursor.com/docs/release-notes)).

**Local-machine access**

20. **Pairing and connectivity design for Remote Control:** explicit pairing approved on the desktop, an outbound-only worker connection so no inbound ports are opened ([My Machines docs](https://cursor.com/docs/cloud-agent/self-hosted/my-machines)), a keep-awake switch with an honest "plugged in, lid open" caveat ([changelog](https://cursor.com/changelog/remote-control-local-agents)), and a clear "disabled" state instead of a generic error ([RSS](https://cursor.com/docs/release-notes/rss.xml)).
21. **Be explicit about handoff semantics.** "Move to Cloud" carries conversation context but not uncommitted files ([help](https://cursor.com/help/ai-features/cloud-agents)); say so in the UI.

**Beyond the app**

22. **Every external entry point ends with a link back into the session:** Slack's plan-first message, short status line, status reactions, overflow menu (add follow-up, switch repository, delete, request ID, feedback) and "Open in Cursor" link ([Slack docs](https://cursor.com/docs/integrations/slack)). Linear's own interview says to keep per-step comments sparse ([Linear blog](https://linear.app/blog/how-cursor-integrated-with-linear-for-agents)).
23. **Agents that wait for events** (PR review, CI result, Slack reply, timer) so the user does not have to poll from a phone ([capabilities docs](https://cursor.com/docs/cloud-agent/capabilities)).
24. **iPad as a different layout,** not a stretched phone: persistent sidebar of chats, review beside chat in split view, full-width diffs, Pencil markup ([iPad changelog](https://cursor.com/changelog/ipad)).
25. **Support hooks in the app:** version footer in the profile sheet, request IDs, and a "report a problem" checklist that asks for the agent ID ([help](https://cursor.com/help/ai-features/mobile-app)). Honor Reduce Motion, as Cursor does for its quick-action pills ([1.9.0 notes](https://cursor.com/docs/release-notes/mobile)).
26. **Admin switches that hide features:** a team admin can hide Projects and gate Remote Control ([1.10.0 notes](https://cursor.com/docs/release-notes/mobile), [docs](https://cursor.com/docs/cloud-agent/mobile)).

### 9.1 Where a new client could beat Cursor (inferred from gaps; not Cursor claims)

A reviewer says approvals go to the laptop and the app is useless in those cases ([App Store feed, 2026-10-10](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json)); Cursor's pages mention approval pushes and a mobile approval sheet for Cloud Agent merge requests on Origin repos, but no tool-approval screen for local agents [unconfirmed: checked the iOS docs, the 2026-10-06 Remote Control entry, the release-notes feed and a forum search; would need the app].

- Spoken replies with an option to skip code ([App Store feed](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json)); copy buttons and text selection that work with tables ([App Store feed](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json)).

## 10. (b) Known pain points from user feedback

Sources are Cursor forum threads (user posts and staff replies), App Store reviews from Apple's RSS feed ([feed](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json)) and a Product Hunt thread. Status words: fixed, open, unknown. Individual reviews are anecdotes, not measurements.

### 10.1 Platform reach

- **iOS 26 only.** Users on iOS 18 and 17 could not install it and asked for support; one developer argued Cursor could build with the new SDK and still target older OS versions. No staff commitment in the thread. Status: open ([release thread 1](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417), [page 2](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2)).
- **No Android.** Staff: planned, no date; the PWA is the fallback, and staff admit it is no full replacement for native background notifications. Requests continued through 2026-10-07. Status: open ([Android thread](https://forum.cursor.com/t/cursor-android-mobile-app/165496), [native app thread](https://forum.cursor.com/t/when-can-we-expect-to-have-native-cursor-mobile-app/163824)).
- **Mainland China unavailable; English only** ([help](https://cursor.com/help/ai-features/mobile-app)). Users asked about China on 2026-06-30 and 2026-07-20, and staff replied on 2026-07-20 that there are no current plans to offer the app in China's App Store ([thread](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417/65)) (corrected 2026-10-15).

### 10.2 Remote Control

- **Agents Window only.** Editor-mode users could not find the setting or `/remote-control`; staff said on 2026-06-30 there were no immediate plans to bring it to the editor window. Status: open ([page 2](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2)).
- **Discoverability and failures.** `/remote-control` missing, doing nothing, or creating a skill instead; requires 3.9.8 or later ([page 2](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2)). Related thread titles that I saw only in the "related topics" lists on [this Windows thread](https://forum.cursor.com/t/ios-app-remote-control-enabled-but-no-option-on-windows-ide/166611) and [this bug report](https://forum.cursor.com/t/remote-control-does-not-work-as-expected/170362), and did not open: "Why don't I have the remote-control function?" (2026-06-30, 11 replies), "/remote-control command missing on latest Cursor" (2026-07-07), "Can't make remote control work" (2026-08-21), "Remote agent Waiting for worker forever" (last activity 2026-09-11) and "Worker disconnected (under remote control)" (2026-09-03). The Windows thread itself was deleted by its author, but Remote Control is offered on Windows and its worker has been broken there for months: since Cursor 3.15.6 (reported 2026-08-09) the Windows worker exits with a better-sqlite3 "NODE_MODULE_VERSION 127 vs 137" error. Staff called it a tracked bug on 2026-08-10 and suggested running the worker under WSL, said on 2026-10-09 that a fix was in progress, and a user still reported it broken with CLI 2026.10.14 on 2026-10-15 ([forum](https://forum.cursor.com/t/windows-remote-control-worker-crashes-better-sqlite3-node-module-version-127-vs-137-cursor-3-15-6/167841)) (corrected 2026-10-15). Discoverability was still a problem in October: on 2026-10-10 a Mac user on Cursor 3.24.12 could not find the setting, and on his Teams account it appeared only after he enabled "Enable Remote Control for Team" under Personal Machines in the web dashboard ([forum](https://forum.cursor.com/t/phone-to-mac-remote-control/174304)).
- **Sessions drop** when the computer sleeps, the lid closes or you switch folders; you must send a message after `/remote-control`; a failed chat should be replaced by a new agent; conversion is not lossless ([staff reply, 2026-09-02](https://forum.cursor.com/t/remote-control-does-not-work-as-expected/170362)).
- **Workspace visibility.** Only open workspaces on a Remote-Control-enabled computer show up; earlier only one workspace per computer could register (fixed); ordinary editor chats do not appear unless handed off; no messaging-style layout yet ([thread, 2026-09-14 to 2026-09-17](https://forum.cursor.com/t/cursor-mobile-and-remote-control-hard-to-use/171650)).
- **Confusing wording and prompts:** a dialog said "cloud agent" when it meant the remotely controlled agent, and asked about including uncommitted changes; staff agreed the term should change ([page 2](https://forum.cursor.com/t/cursor-mobile-app-for-ios/163417?page=2)).
- **Cost of being awake:** the computer must stay on, plugged in, lid open ([changelog](https://cursor.com/changelog/remote-control-local-agents)). Two reviews say the feature does not work or is harder than Codex's (2026-08-26 and 2026-09-07) ([feed](https://itunes.apple.com/us/rss/customerreviews/id=6767085653/sortby=mostrecent/json)).
- **The cloud alternative runs on Ubuntu VMs,** which a Mac and iOS developer called useless for his work ([setup docs](https://cursor.com/docs/cloud-agent/setup), [Nick Dobos post, 2026-06-29](https://x.com/NickADobos/status/2071677855025762754)). Starting new runs on your own Mac through My Machines is documented for the web ([My Machines docs](https://cursor.com/docs/cloud-agent/self-hosted/my-machines)), and staff say it also works from the phone by picking the computer when starting an agent ([staff, 2026-08-21](https://forum.cursor.com/t/cant-make-remote-control-work/169050/5)).
