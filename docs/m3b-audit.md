# M3b implementation and verification

M3b connects the native composer to the M3a write core. Work is in the working tree; no application-repository commits, pushes or branches have been created. The worktree proofs create fixture commits only inside their isolated sandbox repositories. All required local verification commands passed after fixing a shared-catalog cancellation race and strengthening the iPad directory-browser test. The pinned server’s admission-conflict semantics and the unavailable Xcode 27.0 verification are explicitly recorded below.

## Implementation

- `ComposerModel` owns the editing graph separately from the transcript. It uses the shared draft store and M3a admissions, clears input after durable admission, restores rejected creates from the unchanged outbox bytes, and distinguishes staged-revert confirmation from ordinary errors.
- The dock provides attributed mentions, context and command suggestions, shell mode, inline attachments, delivery selection, Stop, model/variant/agent choices, and the pending and saved-input rows. The approval dock remains directly above it. Child sessions explain why their composer is read only.
- Migration v3 adds composer options to drafts. It does not modify existing outbox bodies or preludes. Draft removal invalidates stale debounce writes and removes owned attachment files. Restoring input flushes active composer edits before appending or replacing the draft.
- Prompt encoding uses UTF-16 offsets and the desktop metadata shape. Restoring a prompt reconstructs mention attributes and inline attachment files. ImageIO performs image conversion, downscaling and transcript thumbnail decoding off the main actor.
- The outbox prelude now applies agent, confirmed revert commit, model, then admission. Queue cancellation has a restore option on the existing store path. Undo interrupts without resume, waits, stages a boundary and restores the prompt; Redo leaves the draft alone.
- Shared catalog fetches are owned by the cache, so navigation cannot cancel another consumer’s load. Cache shutdown still cancels its work. Directory entries resolve relative to the server’s scoped directory before displaying their names or navigating.
- New-session views provide project, server-directory, branch and worktree choices. Session actions expose rename, delete, fork, compaction and revert controls. Settings add Follow-up behavior and Show agent using the existing preference suite.
- The UI test cache now persists in its test namespace. The fault proxy can block traffic, drop a forwarded admission response and suppress events while keeping SSE open; normal SSE streams without buffering. The composer-only configuration overlay adds the image/PDF model, variants, primary/hidden/subagents, command and skill without changing the contract and fixture configurations.

## Design and source decisions

- The composer uses a TextKit 2 `UITextView` wrapper. `EditorBehaviorTests` compares the iOS 26 attributed `TextEditor` with a formatting definition against atomic token deletion, and verifies the fallback's deletion, undo and marked-text behavior. A local optional token identity also keeps adjacent mentions of the same target in separate attributed runs; old draft tokens decode without it, and it is excluded from wire encoding. Package and UIKit regression checks cover that case. Both app-hosted checks passed in `.build/m3b-editor-tests.log` and `.build/m3b-editor-tests.xcresult`: the native editor left `@file.swif` after Backspace; the fallback deleted the entire token, restored it with Undo, and retained committed Japanese marked text. The initial fallback test exposed the programmatic Backspace path, which now uses the same atomic edit and undo mechanism.
- The brief's explicit V2-source decisions take precedence: MCP resources are absent, because the server accepts only `data:` and `file://` attachments. This disagrees with ARCHITECTURE §3.2's MCP-resource suggestions.
- **Admission conflict semantics differ from the brief:** d0732ea `packages/core/src/session/inbox.ts` explicitly reconciles the first admission by ID, session and type without preparing or comparing a new payload. Same-session changed-byte replay returns the original admission, not 409. The live contract verifies that behavior and uses a cross-session ID collision to prove the real 409 marks an outbox entry failed. The requested same-session changed-byte 409 proof cannot hold against this pinned server.
- Skill wire entries omit the reference request builder's `name` field: the pinned server accepts only `id` and `mention`, as specified in the brief.
- File searches debounce 120 ms and cancel superseded work, as required by the architecture; the desktop requests on each keystroke. Local suggestions filter their labels; commands filter their trigger or title, without matching descriptions. Session actions disappear from the slash list when there are no visible prompts, and Redo requires a staged boundary. Native case-insensitive subsequence filtering preserves the requested category and server order; it does not reproduce the JavaScript fuzzysort score ordering within each local category. File results come from `fs/find`; the desktop’s editor-tab/recent-file prefix is not included in this milestone’s specified source list.
- `/export`, `/open`, `/terminal`, `/mcp`, `/connect` and `/btw` remain later work. Queued input has Undo, Remove and Steer/Send; in-place queue editing and drag reordering are intentionally absent.
- Images and PDFs unsupported by a model show a dock warning. There is no experimental `fs/write` fallback, unlike the desktop. Every imported attachment goes inline with canonical base64; audio, video and unsupported binary files are refused.
- Native queue rows and controls use at least 44-point touch targets instead of the desktop's 32-point queue rows. Image thumbnails retain 58 × 46 points and radius 6. Their persistent Remove control sits beside the image to provide a 44-point touch target, instead of the desktop hover control. Touch Return inserts a newline; hardware Return sends. Command-period stops instead of cycling agents. Menu-bar command integration remains M6.
- Long-press Send adds Interrupt and send. It admits a steer before requesting interrupt with resume. Staged revert sends require confirmation before the existing confirmed prelude; the desktop commits silently.
- The model picker adds Default, input capability and variant badges, prices per million tokens and five recent models per server. Show all models replaces Manage models and applies within the picker. Release timestamps use the V2 numeric millisecond field; custom models with epoch-zero release dates are hidden until Show all, following the desktop's stale-model rule. The added Recent group retains the last five locally used models even when they are stale. Variant Default is not duplicated when a server also names a variant `default`. The native sheet uses iOS 26’s search placement and navigation chrome rather than the web popover’s top search field; agent and variant options use platform menus.
- V2 agent `id` is the wire selection and mention value; `name` is presentation text. Custom primary agents expose the picker; Show agent defaults off. Hex agent colours accent their controls. Draft selections display Pending while server-selected values remain in the session header.
- Visual comparison corrected the light composer fill to the reference base surface, restored the editor’s 20-point default line height (scaled with Dynamic Type), and kept the reference’s 28-point submit glyph surface inside a 44-point hit target. OCDesign remains dependent on OCRender, without adding a direct wire-model dependency.
- When vertical space is constrained by the keyboard, the composer body scrolls while its toolbar stays visible. Rename uses a native text-entry alert; Delete and reverted-send confirmations use native, scrollable sheets. At accessibility sizes the toolbar separates selection from delivery controls and pending rows put their actions below the text, preserving readable labels and touch targets. The body’s measured scrolling height keeps Send reachable when a restored attachment and revert notice compete with the iPad keyboard.
- Store-owned deletion and pending-input actions continue after optimistic removal dismisses the presenting view or queue panel; their cancellation regression tests pass. Focus requests hand the keyboard to a newly created session and move the caret to the end of restored input.
- The new-session screen uses a neutral title instead of the opencode wordmark. Visual review restored the source’s 880-point content maximum, 25.375% top anchor, centred selectors and 32-point section gaps; with a short keyboard viewport or accessibility text it uses a small top inset and scrolls. Picker controls include the reference disclosure chevrons. The native model control and provider group headings omit provider logos; provider names remain in the model picker. Project and worktree choices follow the desktop flow, with a native directory sheet and branch search. New session retains the active session’s server, and changing the selected server resets the workspace selectors while preserving its separately keyed draft.
- The simulator emits UIKit runtime warnings about `_UIGravityWellEffectAnchorView` and `_UIReparentingView` while presenting SwiftUI’s long-press context menu, and appearance-transition diagnostics during hosted snapshot rendering. The menu interaction passes; these are runtime SDK diagnostics, not compiler warnings. They are retained in the test evidence.

## M3b review fixes

This section records the review pass and supersedes the earlier verification results where behavior changed.

- Undo, Revert message and Edit and resend share a store-owned replacement confirmation. A blank composer or an unchanged previous restore can be replaced directly. Any intervening input or attachment/selection edit requires “Replace your draft?” (Replace/Cancel). The composer is locked while deciding, and Undo performs no interrupt, wait or revert request before approval. Cancelling or removing the store releases the request without changing the draft.
- Directory drafts follow project/worktree selection. Moving to an empty destination retains text, token identities, attachments and choices, and resolves file/reference mentions against their original directory. Conflicting drafts require Keep current draft, Use saved draft or Cancel. Choosing the saved draft preserves the current draft under its original directory; choosing current atomically replaces the destination and keeps its attachment directory.
- Interrupt and send captures the active execution. Admission acknowledgement interrupts only that same execution; a later run or a resync gap delivers an ordinary steer. Waiting uses exponential backoff capped at five seconds rather than a 50 ms loop. Retries/steps retain the execution identity; idle boundaries and unobserved gaps invalidate it before outbox draining can begin. The third delayed-admission case covers this disconnect boundary.
- Sent prompt text again uses the desktop accent. Following `message-content.tsx` / `message-part.css`, sent file/reference/agent mentions inherit that colour with semibold emphasis and a blue-500 `@` prefix; pending input uses normal text. Composer tokens retain their distinct file/agent/reference syntax colours. This refines the original brief’s generic instruction to use mention colours in sent rows. Real-message snapshots now cover mentions plus image and text attachments in both themes, both widths and accessibility5.
- Attachment chips receive encoded bytes and decode base64 and thumbnails in their existing concurrent task, once per source, never inside the transcript body. Editor font and paragraph updates apply only when their computed style changes. Typing attributes explicitly exclude mention tokens and mention colour at a trailing edge. During marked text the editor registers no composer key commands and rejects stale command actions, leaving Return to the IME.
- All four UIKit editor tests are in the standard Opencode test action. The full smoke harness inspects xcresult and requires each case to pass. CI explicitly runs that target on both Xcode versions. Tests use the existing minimal snapshot host, avoiding duplicate package linkage through the application host.
- Proxy blocked mode now destroys the connection without an HTTP response and closes open SSE streams. The offline proof therefore exercises a network failure; lost-response and paused-event modes are unchanged.

### Proposed addition to `docs/design.md`

> The session prompt dock is a raised surface with a 12-point corner radius, a 60–180-point attributed editor and a 44-point toolbar. The approval dock sits immediately above it; queued and saved input share the compact area above the approval dock. At accessibility sizes, selection controls and submit controls occupy separate rows, and pending-input actions wrap below their text. All actionable controls retain 44-point touch targets.
>
> In the editor, file, agent and reference mentions use the property, type and keyword syntax colours respectively. Skills remain plain. Sent prompt bubbles use accent text; file, reference and agent mentions inherit it with semibold emphasis and a lighter `@` prefix, following the desktop transcript. Mentions insert as complete tokens with a trailing space and delete atomically. The editor uses TextKit 2 to preserve token deletion, undo and marked text. Touch Return inserts a newline; hardware Return sends, Shift-Return inserts a newline and Command-Return chooses the alternate delivery. Escape dismisses suggestions, leaves shell mode, then stops a running session. Command-period also stops. While IME marked text is active, hardware commands yield to the input system. Context suggestions use the desktop icons and lists shrink to their content.
>
> Restoring a prompt asks “Replace your draft?” before any session action if there is unsent input, unless the composer still holds an unchanged previous restore. Cancelling preserves the draft and leaves the run and revert boundary alone. Project and worktree changes carry the current draft to an empty destination; conflicting drafts require an explicit choice. File mentions keep their original absolute paths.
>
> Attachments use 58 × 46-point image thumbnails with a 6-point radius, or file cards showing the filename and type. Unsupported model inputs show a warning before sending. Shell mode uses the code font, hides attachment chips and dims selection controls. Empty running composers show Stop; populated running composers show the alternate Steer/Queue action beside Send. Long-press Send exposes Interrupt and send, which interrupts only the execution that was active when selected. If it has ended before admission is acknowledged, the prompt is delivered as an ordinary steer.
>
> Model selection uses a sheet on iPhone and a popover on iPad, with provider groups, five recent models, capability/default/variant badges and per-million-token prices. Agent and variant choices use native menus. Unapplied choices are labelled Pending; the session header reports server-confirmed selections, omitting the default variant and matching the dock's casing for other variants. The new-session workspace uses a neutral title, followed by the composer and centred project/worktree selectors, with an 880-point maximum content width and a 25.375% top anchor. A short keyboard viewport or accessibility text uses a small top inset and a scrollable form. Delete, staged-revert send and draft-replacement confirmations use native sheets fitted to their content, capped by the available height and scrollable at accessibility sizes.
